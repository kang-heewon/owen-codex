# 한국어 구조 짝 사례

구조 역시 단독으로 금지하지 않는다. 관계와 참조가 실제로 필요한지 판단한다.

## 이를 통해

### Rewrite candidate — 빈 연결
Bad: “캐시를 지웠다. 이를 통해 캐시가 삭제되었다.”

Better: “캐시를 지웠다.”

Reason: 두 번째 문장이 같은 사실만 반복한다.

### Preserve — 결과 관계
Good: “읽기 전용 복제본으로 조회를 분산한다. 이를 통해 기본 데이터베이스의 부하를 낮춘다.”

Reason: 앞의 조치와 뒤의 결과 관계를 명확히 연결한다.

## 단순히 A가 아니라 B

### Rewrite candidate — 장식적 대비
Bad: “이 버튼은 단순히 빠른 것이 아니라 편리하다.”

Better: “이 버튼은 빠르고 편리하다.”

Reason: 두 특성 사이에 실질적인 반전이 없다.

### Preserve — 범위 오해 교정
Good: “이 변경은 단순히 로그 형식을 바꾸는 것이 아니라, 로그를 읽는 공개 API 계약도 변경한다.”

Reason: 겉보기 범위와 실제 영향의 중요한 대비를 드러낸다.

## 피동 표현

### Rewrite candidate — 책임 주체 은폐
Bad: “잘못된 권한이 설정되었다.”

Better: “배포 스크립트가 잘못된 권한을 설정했다.”

Reason: 알려진 원인과 책임 주체를 숨기면 진단에 불리하다.

### Preserve — 행위자보다 상태가 중요
Good: “토큰은 발급 후 15분이 지나면 폐기된다.”

Reason: 행위자보다 수명 주기 규칙이 핵심이며 피동 표현이 자연스럽다.

## 해당

### Rewrite candidate — 불필요한 지시어
Bad: “사용자는 해당 버튼을 누른다.”

Better: “사용자는 버튼을 누른다.”

Reason: 가리킬 다른 버튼이 없어 참조를 명확하게 하지 않는다.

### Preserve — 특정 항목 재참조
Good: “검증에 실패한 요청을 목록에서 선택한다. 해당 요청의 오류 세부 정보를 연다.”

Reason: 앞 문장에서 선택한 특정 요청을 다시 가리켜 참조를 분명히 한다.
