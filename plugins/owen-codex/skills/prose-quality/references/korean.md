# 한국어 품질 기준

영어식 안티 슬롭 규칙을 번역해서 적용하지 않는다. 사전적으로 가능한 표현보다 대상 도메인의 한국어 화자가 실제로 자연스럽게 쓰는 표현을 우선하되, 정착된 전문 용어·표준 용어·고유명사·코드 식별자의 의미는 바꾸지 않는다.

## 문맥으로 판단할 문제

다음을 단독 오류가 아니라 문맥상 점검 대상으로 본다.

1. 직역투 어휘와 도메인 레지스터 불일치
2. 영어 문장 구조의 직역
3. 명사화와 한자어 과밀
4. `이`, `이러한`, `이를` 같은 지시어 반복
5. 실제 관계를 설명하지 않는 연결어 과밀
6. 동일 종결어미와 문장 리듬의 기계적 반복
7. 짧은 메시지에 적용된 과한 보고서체
8. 기술 분야의 실무자가 쓰지 않는 번역
9. 정착된 영어 기술 용어를 억지로 번역한 표현
10. 과도한 존댓말과 완곡어 때문에 핵심이 흐려지는 표현

## 도메인 레지스터

소프트웨어 문맥에서는 `컴포넌트를 배선한다`보다 `컴포넌트를 연결한다`, `로깅 계측`보다 구체적인 `메트릭과 트레이싱`, `이벤트를 소비한다`보다 `이벤트를 처리한다`가 자연스러울 수 있다. 그러나 전기 문서의 `배선`, 센서 문서의 `계측`, API exposure의 `노출`, Kafka consumer의 소비 개념, Dependency Injection의 `의존성 주입`, 분산 시스템의 `전파`는 정확한 전문 용어일 수 있다.

`활용`과 `취하다`도 금지어가 아니다. 평범한 문장에서 각각 `사용하다`, `가져오다`가 더 직접적일 수 있지만, 자원 활용률이나 수학에서 값을 취하는 표현은 그대로 두는 편이 정확하다. 같은 단어의 rewrite/preserve 사례는 [../fixtures/ko-register-pairs.md](../fixtures/ko-register-pairs.md)를 따른다.

## 기술 용어의 언어 선택

대상 팀이 instrumentation, consumer, dependency injection, tracing, cache hit, fallback, feature gate 같은 영어 용어를 더 잘 알아본다면 어색한 한국어 신조어를 만들지 않는다. 반대로 자연스러운 한국어를 이유 없이 영어로 치환하지 않는다. 기준은 대상 독자의 도메인 인식과 정확성이다.

## 구조와 리듬

`단순히 A가 아니라 B`, `이는 ~을 의미합니다`, `이를 통해`, `나아가`, `궁극적으로`, `이러한`, `해당`, `~에 대한`, `~을 기반으로`, `~의 관점에서`, `~을 수행하다`, `~을 진행하다`, `~할 수 있도록 한다`는 모두 정상적으로 쓸 수 있다. 실제 관계를 전달하는지, 같은 틀이 반복되는지, 더 짧은 고유 표현이 명확한지를 보고 판단한다. 구조별 false-positive 사례는 [../fixtures/ko-structure-pairs.md](../fixtures/ko-structure-pairs.md)를 참고한다.

문장 길이를 인위적으로 섞지 않는다. 다만 `~합니다`가 길게 반복되거나, 모든 문단이 지시어·연결어로 시작하거나, 명사 중심 문장이 연속되어 독해를 방해하면 같은 레지스터 안에서 리듬을 정리한다.

## 높임말과 문체

`해요체`, `합니다체`, 팀 내부 반말, 외부 공식 문서의 관계를 유지한다. 자연스럽게 보이려고 문체를 섞지 않는다. 명시된 톤과 원문의 말투가 일반적인 스타일 선호보다 우선한다.
